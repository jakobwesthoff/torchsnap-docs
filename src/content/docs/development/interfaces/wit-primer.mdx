[WIT](https://component-model.bytecodealliance.org/design/wit.html)
(WebAssembly Interface Types) is the interface definition language of the
[WebAssembly Component Model](https://component-model.bytecodealliance.org/).
Think of it as the equivalent of Protocol Buffers for WebAssembly: it describes
the functions, types, and error shapes that two sides of a boundary exchange,
without prescribing the implementation language on either side.

For Torchsnap, WIT is the single source of truth for the host-gadget boundary.
The host uses it to generate the Rust code that calls into gadgets. Gadgets use
it (through the SDK or directly) to generate the code that implements those
calls and reaches back into the host. Both sides agree on the same types, the
same function signatures, and the same error variants because they are generated
from the same file.

This page covers the WIT syntax itself. If you are already familiar with WIT
and want to see what the Torchsnap contract provides, head to the
[Introduction](/development/interfaces/) for a feature-oriented overview of
every interface.

## Worlds

WIT organizes contracts into **worlds**. A world declares which interfaces the
component imports (calls into) and which it exports (implements). The Torchsnap
gadget contract defines a single world called `gadget`:

```wit
world gadget {
  // Host capabilities the gadget can call
  import logging;
  import clipboard;
  import sql-storage;
  // ... (14 imports total)

  // Interfaces the gadget must implement
  export lifecycle;
  export search;
  export messaging;
  export tasks;
}
```

The `import` and `export` lines reference named interfaces defined elsewhere in
the same file. What each interface contains is covered in the sections below.

## Interfaces and functions

An `interface` groups related functions and types. Functions are declared with
`func`, listing their parameters and return type:

```wit
interface clipboard {
  write-text: func(text: string) -> result<_, clipboard-error>;
}
```

This declares a `clipboard` interface with one function, `write-text`, that
takes a string and returns either success or a `clipboard-error`.

## Records

A `record` is a named struct with typed fields:

```wit
record action {
  id: action-id,
  label: string,
}
```

## Variants

A `variant` is a tagged union. Each case can optionally carry data:

```wit
variant entry-icon {
  hero-icon(string),
  data-url(string),
  asset-icon(string),
  emoji(string),
}
```

Each case names the kind of icon and carries the value (a Heroicons name, a
base64 data URL, a bundled asset path, or an emoji character).

## Enums

An `enum` is a variant where no case carries data:

```wit
enum post-action { nothing, dismiss, keep-open }
```

## Resources

A `resource` is an opaque handle with methods. The host creates it, the gadget
holds a reference and calls methods on it:

```wit
resource sql-handle {
  execute: func(sql: string, params: list<sql-value>) -> result<u64, string>;
  query: func(sql: string, params: list<sql-value>) -> result<list<list<sql-value>>, string>;
}
```

The gadget obtains an `sql-handle` by calling `connection()` and then uses
`execute` and `query` on it. The host manages the underlying database connection
behind the handle.

## Built-in types

WIT provides a set of generic types used throughout the contract:

- `option<T>`: a value that may be absent (like Rust's `Option` or
  TypeScript's `T | undefined`)
- `result<T, E>`: success or failure (like Rust's `Result`)
- `list<T>`: a variable-length sequence
- `tuple<T, U>`: a fixed-size pair (or triple, etc.)
- `string`, `bool`, `u8`, `u16`, `u32`, `u64`, `s32`, `s64`, `f64`: scalar
  types

## Cross-interface references

The `use` keyword imports types from another interface so they can be shared:

```wit
interface search {
  use types.{entry-icon, action-id, action};
  // ...
}
```

This allows `search` to reference `entry-icon`, `action-id`, and `action`
without redefining them. The `types` interface exists specifically to hold shared
type definitions used by both imports and exports.

## Generating bindings

The WIT file is language-agnostic. Any language that can compile to
`wasm32-wasip2` and produce a valid WebAssembly component can implement the
gadget contract. What differs between languages is how you turn the WIT
definitions into callable code.

### Rust and the SDK

For Rust, the
[wit-bindgen](https://github.com/bytecodealliance/wit-bindgen) project provides
a procedural macro that reads the WIT file at compile time and generates Rust
traits, structs, and function stubs matching the contract. The
`torchsnap-gadget-sdk` crate runs this generation once:

```rust
// Inside torchsnap-gadget-sdk (gadgets/gadget-sdk/src/lib.rs)
wit_bindgen::generate!({
    path: "wit",
    world: "gadget",
    pub_export_macro: true,
    default_bindings_module: "::torchsnap_gadget_sdk",
});
```

This produces the four guest traits (`LifecycleGuest`, `SearchGuest`,
`MessagingGuest`, `TasksGuest`), all the WIT record and variant types
(`CatalogEntry`, `ScoredEntry`, `SearchResponse`, `EntryIcon`, etc.), and the
host import modules (`clipboard`, `http`, `opener`, and so on). The SDK
re-exports everything through its prelude, so your gadget code only needs:

```rust
use torchsnap_gadget_sdk::prelude::*;
```

On top of the raw generated bindings, the SDK adds convenience helpers like
typed settings access, SQL row parsing, and structured logging. These are
covered in the [Imports](/development/interfaces/imports/) reference alongside
the underlying WIT interfaces.

You do not need to run `wit-bindgen` yourself or reference the WIT file directly
when using the SDK. The bindings are pre-generated inside the crate.

### Other languages

<Aside type="note">
  The WIT contract is language-agnostic. If your language has a
  [Component Model bindings generator](https://component-model.bytecodealliance.org/language-support.html)
  (Go, C, C++, JavaScript, and others have varying levels of support), you can
  generate bindings from the WIT file in the SDK repository and implement the
  gadget world directly. The Rust SDK is a convenience layer, not a requirement.
</Aside>

///
/// Minimal initial definition covering lifecycle, catalog search,
/// query search, and execution. Expanded as real gadgets are converted.
package torchsnap:gadget@0.1.0;

/// ─── Host imports (provided by the host to gadgets) ─────
interface logging {
  enum log-level {
    trace,
    debug,
    info,
    warn,
    error,
  }

  /// Structured key-value metadata pair.
  type metadata-entry = tuple<string, string>;

  /// Log a message with optional structured metadata.
  /// The optional span associates this entry with an active span.
  log: func(level: log-level, message: string, metadata: list<metadata-entry>, span: option<u64>);

  /// Start a named timing span. Returns an opaque handle.
  /// Parent allows explicit nesting — pass the parent span's handle.
  /// Metadata attached at start is merged with end-metadata on completion.
  span-start: func(name: string, parent: option<u64>, metadata: list<metadata-entry>) -> u64;

  /// End a timing span. The host computes duration and emits a timing entry.
  /// End-metadata is merged with start-metadata (end wins on key collision).
  span-end: func(span-id: u64, metadata: list<metadata-entry>);
}

/// System clipboard write access.
///
/// WASM gadgets have no direct access to host APIs — they
/// can't reach \`tauri_gadget_clipboard_manager\` the way
/// native gadgets do. This interface exposes a single
/// write-text operation so gadgets can copy results to the
/// clipboard from inside \`execute()\`, \`handle-message\`, or
/// any other guest entry point.
///
/// Read access (paste, query) is intentionally NOT exposed.
/// Reading the clipboard from a sandboxed gadget would let
/// any gadget slurp arbitrary content the user has copied
/// from other applications, which is a privacy footgun.
/// Gadgets that need clipboard read should stay native or
/// wait for an explicit, audited extension of this
/// interface.
interface clipboard {
  /// Error type for clipboard operations.
  variant clipboard-error {
    /// The host clipboard backend reported a failure.
    backend-failure(string),
  }

  /// Write \`text\` to the system clipboard.
  write-text: func(text: string) -> result<_, clipboard-error>;
}

/// Per-gadget SQLite storage.
///
/// Each gadget gets an isolated database file at
/// \`<app_data_dir>/gadget-home/<gadget-id>/sql/storage.sqlite3\`. The host
/// creates the file and applies the migration files declared
/// in \`manifest.toml\`'s \`[storage.sql]\` table before the
/// guest's \`enable()\` runs. Gadgets obtain lightweight
/// connection handles via \`connection()\` and use them to
/// issue queries.
///
/// Gadgets are responsible for scoring, ordering, and
/// \`IN (...)\` expansion on their side — the WIT \`sql-value\`
/// variant intentionally omits the host's internal \`List\`
/// variant. Use \`serde_json\` (or any other serialization)
/// to marshal complex types in and out of \`text\` /
/// \`blob\` columns.
///
/// Bridge-level failures (missing migration file, malformed
/// SQL, filesystem permission) surface as an \`enable()\`
/// error on the host side — the guest never sees them.
/// Per-statement errors surface from \`execute\` / \`query\`.
interface sql-storage {
  /// A database value matching SQLite's five storage classes.
  /// Gadgets build query parameters and read result rows in
  /// terms of this variant.
  variant sql-value {
    null,
    integer(s64),
    real(f64),
    text(string),
    blob(list<u8>),
  }

  resource sql-handle {
    /// Execute a statement that modifies data (INSERT,
    /// UPDATE, DELETE). Returns the number of rows
    /// affected.
    execute: func(sql: string, params: list<sql-value>) -> result<u64, string>;
    /// Execute a SELECT and return all matching rows. Each
    /// row is a list of column values matching the SELECT's
    /// column order.
    query: func(sql: string, params: list<sql-value>) -> result<list<list<sql-value>>, string>;
  }

  /// Obtain a connection handle to the gadget's database.
  connection: func() -> sql-handle;
}

/// Gadget-scoped frecency tracking.
///
/// The host already records selections automatically before
/// dispatching \`execute()\` and applies frecency score bonuses
/// to every query gadget's results after \`search()\` returns
/// — neither path requires the gadget to do anything. This
/// interface exists for the narrower case of gadgets that
/// need to *read* frecency state to drive their own UI.
interface frecency {
  record frecency-item {
    item-id: string,
    score: u32,
  }

  is-enabled: func() -> bool;
  top-items: func(limit: u32) -> list<frecency-item>;
}

/// Read settings from this gadget's namespace.
///
/// Gadgets are confined to keys under \`gadgets.<gadget-id>.\`
/// — the host strips the prefix transparently. Returned values
/// are JSON-encoded strings.
interface settings {
  get: func(key: string) -> option<string>;
}

/// Opens URLs and filesystem paths via the OS default handler chain.
interface opener {
  variant opener-error {
    permission-denied(string),
    invalid-url(string),
    backend-failure(string),
  }

  open-url: func(url: string) -> result<_, opener-error>;
  open-path: func(path: string) -> result<_, opener-error>;
  reveal-path: func(path: string) -> result<_, opener-error>;
}

/// Minimal synchronous HTTP client for WASM gadgets.
interface http {
  variant http-method {
    get, post, put, patch, delete, head,
    other(string),
  }

  record http-request {
    url: string,
    method: http-method,
    headers: list<tuple<string, string>>,
    body: option<list<u8>>,
    timeout-ms: option<u32>,
    max-body-size: option<u64>,
    insecure-tls: bool,
  }

  record http-response {
    status: u16,
    headers: list<tuple<string, string>>,
    body: list<u8>,
  }

  variant http-error {
    permission-denied(string),
    connection-refused(string),
    timeout,
    dns-failed(string),
    tls-failed(string),
    invalid-url(string),
    other(string),
  }

  fetch: func(request: http-request) -> result<http-response, http-error>;
}

/// Read-only access to host filesystem paths declared in the manifest.
interface filesystem {
  variant fs-error {
    permission-denied(string),
    invalid-path(string),
    not-found,
    io(string),
  }

  record file-metadata {
    size: u64,
    modified-unix-ms: u64,
    is-symlink: bool,
  }

  read-file: func(path: string) -> result<list<u8>, fs-error>;
  file-exists: func(path: string) -> bool;
  metadata: func(path: string) -> result<file-metadata, fs-error>;
}

/// Per-gadget asset access. Always available, no permission needed.
interface assets {
  variant assets-error {
    invalid-path(string),
    not-found,
    io-error(string),
  }

  read: func(path: string) -> result<list<u8>, assets-error>;
  exists: func(path: string) -> result<bool, assets-error>;
}

/// Run a system process and capture its output.
interface command {
  record command-options {
    args: list<string>,
    cwd: option<string>,
    env: list<tuple<string, string>>,
    stdin: option<list<u8>>,
    timeout-ms: option<u32>,
    max-output-bytes: option<u64>,
  }

  record command-result {
    exit-code: option<s32>,
    signal: option<string>,
    timed-out: bool,
    stdout: list<u8>,
    stderr: list<u8>,
  }

  variant command-error {
    permission-denied(string),
    spawn-failed(string),
    timeout,
    output-too-large(tuple<list<u8>, list<u8>>),
  }

  run: func(binary: string, options: command-options) -> result<command-result, command-error>;
}

/// Runtime OS and CPU architecture detection.
interface platform {
  variant os { macos, linux, windows, other(string) }
  variant arch { x86-64, aarch64, other(string) }

  current-os: func() -> os;
  current-arch: func() -> arch;
}

/// Resolve manifest substitution variables at runtime.
interface path-resolver {
  variant resolve-error {
    unknown-variable(string),
    unterminated(string),
  }

  resolve: func(template: string) -> result<string, resolve-error>;
}

interface lifecycle {
  enable: func() -> result<_, string>;
  disable: func();
  on-setting-changed: func(key: string, value: string);
}

interface types {

    hero-icon(string),
    data-url(string),
    asset-icon(string),
    emoji(string),
  }

  variant action-id {
    open, copy, reveal, open-with, delete, open-settings,
    custom(string),

  record action {
    id: action-id,
    label: string,
  }
}

  record catalog-entry {
    id: string,
    title: string,
    subtitle: option<string>,
    icon: option<entry-icon>,
    keywords: list<string>,
    actions: list<action>,
  }

  record scored-entry {
    id: string,
    title: string,
    subtitle: option<string>,
    icon: option<entry-icon>,
    score: u32,
    title-highlight-positions: list<u32>,
    subtitle-highlight-positions: list<u32>,
    actions: list<action>,
    data: option<string>,
  }

  record view-response {
    view: string,
    data: option<string>,
    results: list<scored-entry>,
  }

    custom-ui(view-response),
    inline-ui(view-response),

  execute: func(entry: scored-entry, action-id: action-id) -> result<post-action, string>;
}

interface tasks {

}

/// Shared host service for website metadata (title, description, favicon).

    description: option<string>,
    favicon: entry-icon,
  }

  variant lookup-result {
    hit(cache-entry),
    reachable-no-data,
    unreachable,
    pending,
  }

  variant website-metadata-error {
    permission-denied(string),
    invalid-domain(string),
  }

  lookup: func(domain: string, mode: lookup-mode) -> result<lookup-result, website-metadata-error>;
}
